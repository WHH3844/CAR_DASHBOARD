# CAR_DASHBOARD 架构版测试步骤

## 1. 编译与烧录

1. 用 Keil 打开 `Project/CAR_DASHBOARD.uvprojx`。
2. 默认保持 `Config/App_Cfg.h` 中：

```c
#define APP_CFG_USE_FREERTOS 1u
```

3. Build 工程。
4. 若需要排查 RTOS tick、任务栈或中断优先级问题，再临时改为 `0u` 回退裸机 super loop 做对比。
5. 若有编译错误，优先处理 include 路径、重复定义、函数声明不一致。
6. 烧录后打开串口，波特率 `115200`。
7. 正常启动后应看到类似日志：

```text
[INFO] CAR_DASHBOARD EcuM boot
[INFO] CanIf CAN1 500K online
[INFO] EcuM enter RUN, FreeRTOS enabled
[INFO] Os creating FreeRTOS EcuM task
```

## 2. LCD 与按键基础测试

1. 上电后 LCD 应显示正式架构界面，不再进入旧的 `12_dashboard_demo`。
2. 屏幕应显示：
   - 左侧转速表盘，指针随 `0x321 EngineSpeed` 变化
   - 右侧车速表盘，指针随 `0x321 VehicleSpeed` 变化
   - 中央大号数字车速和当前档位
   - 顶部 CAN/SIM 状态和 MIL/ABS/AIR/BRK/TPMS 告警提示
   - 底部燃油、水温、电压、时间、座舱温湿度和四轮胎压区域
3. 不发 CAN 时，CAN 状态应变为 `CAN LOST`。
4. KEY1：进入/退出模拟数据模式，速度和转速应自动变化。
5. KEY2：切换蜂鸣器静音。
6. KEY3：清零速度和转速。
7. 长按电源键：应先执行 `NvM_WriteAll()`，再软关机。

## 3. CAN 业务报文测试

USB-CAN 设置：

- Standard CAN
- 500K
- DLC = 8
- 输入报文周期建议先用 `20ms`、`50ms` 或 `100ms`

### 3.1 报文矩阵与当前开发状态

CAN 报文矩阵中定义了 `0x321~0x328`，但不是所有报文都会由板子主动发送。PCAN-VIEW 里能看到什么，取决于该报文是“外部 ECU 输入给仪表”，还是“仪表输出到总线”。

| CAN ID | 报文名 | 方向 | 当前开发状态 | PCAN-VIEW 现象 |
|---|---|---|---|---|
| `0x321` | `EMS_Powertrain_20ms` | 外部 ECU -> 仪表 | 已解析 | 需要 PCAN 主动周期发送；板子收到后更新车速/转速 |
| `0x322` | `BCM_BodyStatus_100ms` | 外部 ECU -> 仪表 | 已解析基础字段 | 需要 PCAN 主动发送；板子不会主动发 |
| `0x323` | `TPMS_Status_1000ms` | 外部 ECU -> 仪表 | 已解析并写入 RTE | 需要 PCAN 主动发送；当前 UI 暂不显示胎压 |
| `0x324` | `IHU_CGW_Config_500ms` | 外部 ECU -> 仪表 | 已解析配置并运行期同步背光 | 需要 PCAN 主动发送；用于测试背光配置 |
| `0x325` | `ICM_Status_100ms` | 仪表 -> 总线 | 已发送 | 板子周期发送，PCAN 应能看到 |
| `0x326` | `ICM_DiagStatus_1000ms` | 仪表 -> 总线 | 已发送 | 板子周期发送，PCAN 应能看到 |
| `0x327` | `ICM_UserInput_Event` | 仪表 -> 总线 | 已发送 | KEY1/KEY2/KEY3 触发时事件发送 |
| `0x328` | `ICM_LogStatus_1000ms` | 仪表 -> 总线 | 已发送 | 板子周期发送，PCAN 应能看到 |

当前代码对应关系：

- 接收入口：`Bsw/Communication/CanIf/CanIf.c` -> `CanIf_MainFunction()`
- 路由入口：`Bsw/Communication/PduR/PduR.c` -> `PduR_RxIndication()`
- 业务解析：`Bsw/Communication/Com/Com.c` -> `Com_RxIndication()`
- 周期发送：`Bsw/Communication/Com/Com.c` -> `Com_MainFunction()`
- 底层发送：`Bsw/Communication/CanIf/CanIf.c` -> `CanIf_Transmit()`

因此，PCAN-VIEW 中如果没看到某些 ID，先按下面规则判断：

- `0x322/0x323/0x324` 是输入报文，必须由 PCAN 或其它节点主动发。
- `0x327` 是事件报文，只有按键触发时才会出现；不是周期报文。
- `0x328` 是周期报文，烧录补齐后的程序后应能看到；当前会上报日志使能和运行秒数，TF 卡日志字段先按未挂载/无错误处理。
- `0x440` 是当前代码额外发送的简化 NM 报文，不在 `0x321~0x328` 业务报文区间内。

### 3.2 PCAN-VIEW 输入报文测试

#### 3.2.1 发送 0x321 EMS_Powertrain_20ms

```text
CAN ID: 0x321
Data : 00 05 10 27 C8 5A 41 78
Cycle: 20ms 或 50ms
```

含义：

- 车速 raw = `0x0500` = 1280，物理值 = 1280 * 0.0625 = 80.0 km/h
- 转速 raw = `0x2710` = 10000，物理值 = 10000 * 0.25 = 2500 rpm
- 油量 raw = `0xC8`，物理值约 80%
- 水温 raw = `0x5A`，物理值 = 90 - 40 = 50 C
- 外温 raw = `0x41`，物理值 = 65 - 40 = 25 C
- 电压 raw = `0x78`，当前代码暂按 0.1V/bit，即 12.0V

期望现象：

- LCD 显示约 `80 km/h`
- LCD 显示约 `2500 rpm`
- CAN 状态从 `CAN LOST` 变为 `CAN OK`
- 板子周期发送 `0x325 ICM_Status_100ms`
- 板子周期发送 `0x326 ICM_DiagStatus_1000ms`

注意：

- `0x321` 的真实矩阵周期是 `20ms`。
- 当前代码的动力 CAN 超时阈值是 `500ms`。
- 如果 PCAN 里把 `0x321` 设置为 `500ms`，由于 PCAN 调度和 MCU 主循环存在抖动，可能刚好超过阈值，导致 `0x325 Byte5` 仍显示 `00`。
- 建议测试时把 `0x321` 周期设置为 `20ms`、`50ms` 或 `100ms`；此时 `0x325 Byte5` 应变为 `01`。

#### 3.2.2 发送 0x322 BCM_BodyStatus_100ms

`0x322` 当前解析规则在 `Com_DecodeBodyStatus()` 中：

- `Byte0 bit0-1`：点火状态
- `Byte0 bit2-5`：档位
- `Byte3 bit0-3`：MIL/ABS/Airbag/Brake 等故障灯，汇总进 `warning_flags`

示例：

```text
CAN ID: 0x322
Data : 0D 00 00 05 00 00 00 00
Cycle: 100ms
```

含义：

- `Byte0 = 0x0D`
  - bit0-1 = `1`，表示点火状态示例值
  - bit2-5 = `3`，表示 `D` 档
- `Byte3 = 0x05`，表示故障灯位图示例值

期望现象：

- LCD 中央档位应显示 `D`；如果改回 `0x09`，档位会显示 `N`。
- 代码会把数据写入 RTE，并在 `0x325 Byte6` 回传 `warning_flags`。
- 若发送上面的示例，PCAN 中 `0x325` 的 `Byte6` 应能看到 `05`。

#### 3.2.3 发送 0x323 TPMS_Status_1000ms

`0x323` 当前解析四轮胎压和胎温，并写入 RTE：

```text
CAN ID: 0x323
Data : 64 64 64 64 5A 5A 5A 5A
Cycle: 1000ms
```

含义：

- `Byte0-3 = 0x64`，胎压 raw=100，物理值 = 100 * 0.0275 = 2.75 bar
- `Byte4-7 = 0x5A`，胎温 raw=90，物理值 = 90 - 40 = 50 C

期望现象：

- 当前不会改变 LCD 显示。
- 当前不会改变 `0x325/0x326` 的主要字段。
- 可通过调试器观察 `Rte_TpmsData`，确认四轮胎压/胎温和 valid 位已经更新。

#### 3.2.4 发送 0x324 IHU_CGW_Config_500ms

`0x324` 当前按矩阵解析配置，`Byte1` 作为背光百分比：

```text
CAN ID: 0x324
Data : 00 64 50 D2 04 01 0C 22
Cycle: 500ms
```

含义：

- `Byte0 = 0x00`，Auto/中文/公制
- `Byte1 = 0x64 = 100`，背光等级 100%
- `Byte2 = 0x50 = 80`，报警音量目标值 80%
- `Byte3-4 = 0x04D2 = 1234 km`，续航里程示例
- `Byte5 bit0 = 1`，外部时间有效
- `Byte6 = 0x0C`，小时 12
- `Byte7 = 0x22`，分钟 34

也可以测试关闭背光：

```text
CAN ID: 0x324
Data : 00 00 50 D2 04 01 0C 22
Cycle: 500ms
```

期望现象：

- `Byte1 = 0` 时，RTE 背光等级写为 0，`App_Display` 会在运行期同步到 `BacklightIf`。
- `Byte1 = 100` 时，背光恢复打开。

### 3.3 板子当前主动发送项

#### 3.3.1 0x325 ICM_Status_100ms

板子周期发送 `0x325`，当前打包规则：

```text
Byte0-1: vehicle_speed_kph_x10，小端，单位 0.1km/h
Byte2-3: engine_rpm，小端，单位 rpm
Byte4  : bit0 alarm_active，bit1 buzzer_muted，bit2 simulation_mode
Byte5  : can_ems_valid，1 表示 0x321 当前有效
Byte6  : warning_flags，来自 0x322 Byte3
Byte7  : rolling counter
```

例如 PCAN 收到：

```text
0x325: E8 03 B8 0B 00 01 05 XX
```

表示：

- 车速 `0x03E8 = 1000` -> `100.0 km/h`
- 转速 `0x0BB8 = 3000 rpm`
- `Byte4 = 00` -> 无报警、未静音、非模拟
- `Byte5 = 01` -> 动力 CAN 当前有效
- `Byte6 = 05` -> 车身告警位图为 `0x05`
- `Byte7 = XX` -> 计数器

#### 3.3.2 0x326 ICM_DiagStatus_1000ms

板子周期发送 `0x326`，当前打包规则：

```text
Byte0: confirmed DTC 数量
Byte1: 当前诊断会话，0x01 default，0x03 extended
Byte2: 动力 CAN 有效位，1 表示 0x321 当前有效
Byte3-6: 预留
Byte7: rolling counter
```

例如：

```text
0x326: 01 01 01 00 00 00 00 XX
```

表示：

- 当前有 1 个历史 confirmed DTC
- 当前处于默认会话
- 动力 CAN 当前有效
- DTC 数量为 1 不代表当前仍故障，可能是之前超时留下的历史 DTC，需要通过 UDS `0x14` 清除

#### 3.3.3 0x440 简化 NM

当前代码额外发送 `0x440`：

```text
Byte0: 0x28，教学用 ICM 节点地址
Byte2: 0x01，RUN 状态
Byte7: rolling counter
```

该报文用于确认仪表节点仍在运行，不属于 `0x321~0x328` 业务报文矩阵。

#### 3.3.4 0x327 ICM_UserInput_Event

`0x327` 是事件报文，不是周期报文。按下 KEY1/KEY2/KEY3 并通过去抖后，板子会发送一次：

```text
Byte0: KeyCode，1 KEY1，2 KEY2，3 KEY3，4 POWER
Byte1: KeyAction，1 ShortPress，2 LongPress
Byte2: EventCounter
Byte3: bit0 PowerKeyLongPress，bit1 ShutdownConfirm
Byte4-7: 预留
```

例如按 KEY1：

```text
0x327: 01 01 XX 00 00 00 00 00
```

#### 3.3.5 0x328 ICM_LogStatus_1000ms

`0x328` 当前周期发送日志状态：

```text
Byte0 bit0-1: SdCardStatus，当前 0 NotMounted
Byte0 bit2  : LogEnable，当前 1
Byte1-2     : CurrentLogFileIndex，当前 0
Byte3       : LogWriteErrorCounter，当前 0
Byte4-7     : RuntimeSeconds，小端
```

例如：

```text
0x328: 04 00 00 00 2A 00 00 00
```

表示串口日志使能，运行时间 42 秒。

## 4. UDS 诊断测试

诊断请求：

- 物理请求 ID：`0x700`
- 响应 ID：`0x708`
- 功能请求 ID：`0x7DF`
- 当前推荐使用 ISO-TP 单帧格式

### 4.1 进入扩展会话

发送：

```text
ID 0x700: 02 10 03 00 00 00 00 00
```

期望响应：

```text
ID 0x708: 06 50 03 00 32 13 88 00
```

### 4.2 TesterPresent

发送：

```text
ID 0x700: 02 3E 00 00 00 00 00 00
```

期望响应：

```text
ID 0x708: 02 7E 00 00 00 00 00 00
```

### 4.3 读取当前车速 DID 0xF181

发送：

```text
ID 0x700: 03 22 F1 81 00 00 00 00
```

若当前车速为 80.0 km/h，RTE 内部为 `800 = 0x0320`，期望响应：

```text
ID 0x708: 05 62 F1 81 03 20 00 00
```

### 4.4 读取当前转速 DID 0xF182

发送：

```text
ID 0x700: 03 22 F1 82 00 00 00 00
```

若当前转速为 2500 rpm，期望响应：

```text
ID 0x708: 05 62 F1 82 09 C4 00 00
```

### 4.5 读取 DTC 数量

发送：

```text
ID 0x700: 03 19 01 FF 00 00 00 00
```

期望响应：

```text
ID 0x708: 06 59 01 FF 01 00 XX 00
```

其中 `XX` 是当前匹配状态掩码的 DTC 数量。

### 4.6 读取首个 DTC

发送：

```text
ID 0x700: 03 19 02 FF 00 00 00 00
```

无故障时：

```text
ID 0x708: 03 59 02 FF 00 00 00 00
```

有故障时：

```text
ID 0x708: 07 59 02 FF <DTC_H> <DTC_M> <DTC_L> <STATUS>
```

### 4.7 清除 DTC

需要先进入扩展会话，再发送：

```text
ID 0x700: 04 14 FF FF FF 00 00 00
```

期望响应：

```text
ID 0x708: 01 54 00 00 00 00 00 00
```

## 5. NvM 掉电保存测试

1. 烧录运行一次，观察启动日志。
2. 关机或复位。
3. 再次读取 DID `0xF180` 启动次数：

```text
ID 0x700: 03 22 F1 80 00 00 00 00
```

期望启动次数递增。

## 6. FreeRTOS 运行测试

当前代码已经接入 FreeRTOS，并默认开启。确认步骤：

1. 确认 `Config/App_Cfg.h` 中：

```c
#define APP_CFG_USE_FREERTOS 1u
```

2. 编译并烧录。
3. 串口应出现 `EcuM enter RUN, FreeRTOS enabled` 和 `Os creating FreeRTOS EcuM task`。
4. LCD、CAN、UDS、NvM 测试步骤与前面一致。
5. 若启动后没有进入 RUN，优先检查：
   - `FreeRTOSConfig.h` 中中断优先级
   - `SysTick_Handler/PendSV_Handler/SVC_Handler` 是否被正确映射
   - `APP_CFG_FREERTOS_ECUM_STACK` 是否足够
   - `configTOTAL_HEAP_SIZE` 是否足够
   - LCD 刷新是否耗时过长，导致 10ms 主任务节拍被拖慢
6. 若需要确认问题是否由 RTOS 引入，把 `APP_CFG_USE_FREERTOS` 临时改为 `0u`，重新编译烧录，观察裸机 super loop 下是否恢复正常。
