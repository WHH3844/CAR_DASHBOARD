# CAR_DASHBOARD 架构版测试步骤

## 1. 编译与烧录

1. 用 Keil 打开 `Project/CAR_DASHBOARD.uvprojx`。
2. 默认保持 `Config/App_Cfg.h` 中：

```c
#define APP_CFG_USE_FREERTOS 1u
```

3. Build 工程。
4. 若需要排查 RTOS tick、任务栈或中断优先级问题，再临时改为 `0u` 回退裸机 super loop 做对比。
5. 若有编译错误，优先处理 include 路径、重复定义、函数声明不一致。
6. 烧录后打开串口，波特率 `115200`。
7. 正常启动后应看到类似日志：

```text
[INFO] CAR_DASHBOARD EcuM boot
[INFO] CanIf CAN1 500K online
[INFO] EcuM enter RUN, FreeRTOS enabled
[INFO] Os creating FreeRTOS EcuM task
```

## 2. LCD 与按键基础测试

1. 上电后 LCD 应显示正式架构界面，不再进入旧的 `12_dashboard_demo`。
2. 屏幕应显示：
   - SPEED
   - RPM
   - TIME
   - TEMP
   - HUM
   - CAN OK / CAN LOST
3. 不发 CAN 时，CAN 状态应变为 `CAN LOST`。
4. KEY1：进入/退出模拟数据模式，速度和转速应自动变化。
5. KEY2：切换蜂鸣器静音。
6. KEY3：清零速度和转速。
7. 长按电源键：应先执行 `NvM_WriteAll()`，再软关机。

## 3. CAN 业务报文测试

USB-CAN 设置：

- Standard CAN
- 500K
- DLC = 8
- 周期发送建议 20ms

发送 `0x321 EMS_Powertrain_20ms`：

```text
CAN ID: 0x321
Data : 00 05 10 27 C8 5A 41 78
```

含义：

- 车速 raw = `0x0500` = 1280，物理值 = 1280 * 0.0625 = 80.0 km/h
- 转速 raw = `0x2710` = 10000，物理值 = 10000 * 0.25 = 2500 rpm
- 油量 raw = `0xC8`，物理值约 80%
- 水温 raw = `0x5A`，物理值 = 90 - 40 = 50 C
- 外温 raw = `0x41`，物理值 = 65 - 40 = 25 C
- 电压 raw = `0x78`，当前代码暂按 0.1V/bit，即 12.0V

期望现象：

- LCD 显示约 `80 km/h`
- LCD 显示约 `2500 rpm`
- CAN 状态从 `CAN LOST` 变为 `CAN OK`
- 板子周期发送 `0x325 ICM_Status_100ms`
- 板子周期发送 `0x326 ICM_DiagStatus_1000ms`

## 4. UDS 诊断测试

诊断请求：

- 物理请求 ID：`0x700`
- 响应 ID：`0x708`
- 功能请求 ID：`0x7DF`
- 当前推荐使用 ISO-TP 单帧格式

### 4.1 进入扩展会话

发送：

```text
ID 0x700: 02 10 03 00 00 00 00 00
```

期望响应：

```text
ID 0x708: 06 50 03 00 32 13 88 00
```

### 4.2 TesterPresent

发送：

```text
ID 0x700: 02 3E 00 00 00 00 00 00
```

期望响应：

```text
ID 0x708: 02 7E 00 00 00 00 00 00
```

### 4.3 读取当前车速 DID 0xF181

发送：

```text
ID 0x700: 03 22 F1 81 00 00 00 00
```

若当前车速为 80.0 km/h，RTE 内部为 `800 = 0x0320`，期望响应：

```text
ID 0x708: 05 62 F1 81 03 20 00 00
```

### 4.4 读取当前转速 DID 0xF182

发送：

```text
ID 0x700: 03 22 F1 82 00 00 00 00
```

若当前转速为 2500 rpm，期望响应：

```text
ID 0x708: 05 62 F1 82 09 C4 00 00
```

### 4.5 读取 DTC 数量

发送：

```text
ID 0x700: 03 19 01 FF 00 00 00 00
```

期望响应：

```text
ID 0x708: 06 59 01 FF 01 00 XX 00
```

其中 `XX` 是当前匹配状态掩码的 DTC 数量。

### 4.6 读取首个 DTC

发送：

```text
ID 0x700: 03 19 02 FF 00 00 00 00
```

无故障时：

```text
ID 0x708: 03 59 02 FF 00 00 00 00
```

有故障时：

```text
ID 0x708: 07 59 02 FF <DTC_H> <DTC_M> <DTC_L> <STATUS>
```

### 4.7 清除 DTC

需要先进入扩展会话，再发送：

```text
ID 0x700: 04 14 FF FF FF 00 00 00
```

期望响应：

```text
ID 0x708: 01 54 00 00 00 00 00 00
```

## 5. NvM 掉电保存测试

1. 烧录运行一次，观察启动日志。
2. 关机或复位。
3. 再次读取 DID `0xF180` 启动次数：

```text
ID 0x700: 03 22 F1 80 00 00 00 00
```

期望启动次数递增。

## 6. FreeRTOS 运行测试

当前代码已经接入 FreeRTOS，并默认开启。确认步骤：

1. 确认 `Config/App_Cfg.h` 中：

```c
#define APP_CFG_USE_FREERTOS 1u
```

2. 编译并烧录。
3. 串口应出现 `EcuM enter RUN, FreeRTOS enabled` 和 `Os creating FreeRTOS EcuM task`。
4. LCD、CAN、UDS、NvM 测试步骤与前面一致。
5. 若启动后没有进入 RUN，优先检查：
   - `FreeRTOSConfig.h` 中中断优先级
   - `SysTick_Handler/PendSV_Handler/SVC_Handler` 是否被正确映射
   - `APP_CFG_FREERTOS_ECUM_STACK` 是否足够
   - `configTOTAL_HEAP_SIZE` 是否足够
   - LCD 刷新是否耗时过长，导致 10ms 主任务节拍被拖慢
6. 若需要确认问题是否由 RTOS 引入，把 `APP_CFG_USE_FREERTOS` 临时改为 `0u`，重新编译烧录，观察裸机 super loop 下是否恢复正常。
