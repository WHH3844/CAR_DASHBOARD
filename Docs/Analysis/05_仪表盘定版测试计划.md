## 1. 目标与环境

目标：验证 v1.0 CAN、UDS、Dem、NvM 和控制域接口与代码、矩阵一致。

建议环境：

- Keil MDK ARMCC 5.06 update 7
- GD32F470ZGT6 目标板
- PCAN-USB 或等效 CAN 工具，500 kbit/s
- UDS 测试脚本或 PCAN 手工发送
- 串口日志和 LCD 同时观察
- 可选：S32K144 控制域板

所有数值除特别说明外均以十六进制填写。标准 CAN 信号按矩阵 LE；UDS 多字节数值按 BE。

## 3. PCAN 接收测试

### 0x321 Powertrain

| 用例 | 发送帧 | 预期 |
|---|---|---|
| CAN-RX-321-01 | `0x321: E8 03 20 03 32 64 28 7D` | 车速 raw=1000 -> 100.0 km/h；转速 800 rpm；其余有效 |
| CAN-RX-321-02 | `0x321: FF 1F FF FF FF FF FF FF` | 六个信号均无效；UI 不出现异常大值 |
| CAN-RX-321-03 | 停止发送超过 100 ms | Powertrain freshness 失效并触发接收超时监控 |

### 0x322 Body

|---|---|---|
| CAN-RX-322-01 | `0x322: 2D 1F 17 0F 01 80 00 00` | 点火/挡位、四门、安全带、灯光/转向/驻车、四故障灯、洗涤液和环境光均按位显示 |

### 0x329 Control Domain Status

CRC8/J1850 覆盖字节：`29 03 B0 B1 B2 B3 B4 B5 B6`。可直接使用的正常样例：

```text
0x329  DLC=8  10 09 00 53 FF FF 01 67
```

该帧表示 v1.0、ADC、RUN、Health=OK、CAN1/CAN2/ADC/SelfTest 正常、无远端故障、Alive=1，末字节 `0x67` 为 CRC8/J1850。

| 用例 | 步骤 | 预期 |
|---|---|---|
| CAN-RX-329-01 | 发送 `10 09 00 53 FF FF 01 67`，并周期发送 0x441 | UI 显示 CDM Online/OK/ADC/RUN |
| CAN-RX-329-02 | CRC 改错 1 bit | 丢弃帧，不更新时间戳 |
| CAN-RX-329-03 | AliveCounter 固定，连续发送 | 判定发送任务疑似冻结并降级 |
| CAN-RX-329-04 | Version 非 10 | 标记接口版本不兼容 |
| CAN-RX-329-05 | 停止发送超过 1500 ms | 应用状态 stale，本机仪表继续工作 |

### 0x441 NM

| 用例 | 步骤 | 预期 |
|---|---|---|
| CAN-RX-441-01 | 周期发送合法 NM | CDM NM online |
| CAN-RX-441-02 | 停止发送超过 3000 ms | CDM NM offline，不影响 0x329 独立状态机 |

## 7. 显示与降级回归

1. 正常动力/车身/TPMS 帧下 UI 数值和图标正确。
2. 任一单信号无效时只影响对应显示，不把整车状态全部清空。
3. 控制域离线时，LCD、按键、RTC、SHT30、本地 UDS 继续工作。
4. 本地故障和远端故障分开展示。
5. 无 FatFs 时不显示“文件日志正常”。
6. 低电压、显示初始化失败、SDRAM 失败等既有故障路径回归。
