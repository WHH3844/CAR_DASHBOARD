# CAR_DASHBOARD 仪表盘工程完整性评估

版本：v1.0  
日期：2026-07-29

## 1. 总体评价

工程已具备可运行的分层骨架、FreeRTOS 任务、板级外设驱动、仪表 UI、CAN/UDS/Dem/NvM 教学链路和 Keil 构建工程。其完整度适合作为仪表盘原型和教学工程，但距离量产软件仍缺少完整 ISO-TP、真实文件系统日志、全面故障监控、NvM 冗余/原子写、总线端到端保护和系统级自动化测试。

本轮的目标是让“已经实现的能力”与矩阵、代码和测试证据一致，而不是用文档把未实现功能包装成已完成。

## 2. 十三维完整性分级

状态仅使用 `Complete / Partially Complete / Stub / Not Implemented / Not Required`。`Complete` 表示当前仪表盘原型范围内代码、配置和已有验证证据闭环，不等同于量产 ASIL 软件成熟度。

| 维度 | 状态 | 源码/文档证据 | 剩余缺口 |
|---|---|---|---|
| 1. 硬件 Bring-up | Complete | Mcal 中 LCD、SDRAM、RTC、SHT30、EEPROM、CAN 驱动及既有硬件调试记录 | 换板或改版后仍需重复板级验收 |
| 2. 启动与电源管理 | Partially Complete | EcuM、App_Power、保持电源与关机请求主路径存在 | 低压/掉电时序和异常断电需实板验证 |
| 3. FreeRTOS 与任务框架 | Complete | Os 任务创建、周期调度、看门狗喂狗链路已接入当前 Keil 工程 | 产品化仍需 WCET、栈水位和长期压力测试 |
| 4. CAN 业务接口 | Partially Complete | Com/PduR/CanIf 及 0x321..0x329、0x440/0x441 v1.0 映射已落地 | PCAN 实车帧回放和总线异常台架尚未执行 |
| 5. 信号有效性与超时 | Partially Complete | Rte 逐信号有效位、报文 freshness、0x329 CRC/Alive 和 0x441 NM 独立监督 | 边界值、乱序和高负载下的动态验证待台架完成 |
| 6. HMI 显示与人机交互 | Partially Complete | App_Display 使用动力、17 项车身、逐轮 TPMS 和控制域状态；按键链路存在 | 所有组合告警、日夜主题和可读性需实屏验收 |
| 7. UDS | Partially Complete | Dcm 支持 0x10/0x22/0x19/0x14/0x3E 单帧，DID 唯一且数值 BE | 完整 ISO-TP、多帧和更多服务未实现 |
| 8. Dem | Partially Complete | 20 项事件定义、9 项直接监控、阈值去抖和确认语义已落地 | 11 项尚无完整真实监控，快照/扩展数据未实现 |
| 9. NvM | Partially Complete | 当前三块地址、CRC、版本和 dirty 状态可用 | 大块、双副本、原子提交和磨损均衡未实现 |
| 10. 文件日志 | Stub | 0x328 和 UI 明确报告未挂载/Stub | FatFs 挂载、文件轮转和断电一致性未实现 |
| 11. 降级与故障隔离 | Partially Complete | 控制域离线不阻断本机 LCD/按键/RTC/UDS；无效信号使用安全占位 | 低压、总线拥塞和多故障叠加需故障注入 |
| 12. 自动化与回归测试 | Partially Complete | 工作簿契约校验、公式扫描、26 表视觉检查、Keil 0/0 构建已通过 | PCAN/UDS/断电/长稳仍依赖台架 |
| 13. S32K144 对接就绪度 | Partially Complete | GD32/S32 接口 v1.0、0x329 和按键引脚冲突表已冻结 | S32 侧实现、双板联调和电气确认尚未完成 |

结论：工程可作为 **Partially Complete 的可联调仪表盘原型** 进入 S32K144 接口实现阶段；在 PCAN、UDS、断电与双板台架完成前，不得宣称整车接口验收完成。

## 3. 分层和模块状态

| 层/模块 | 状态 | 评价 |
|---|---|---|
| App Dashboard / Display / Key / Power / Sensor | 部分完成 | 主路径可运行；远端状态显示和更多车身/TPMS 状态需补齐 |
| Rte Signal / Event / Service | 部分完成 | 具备轻量解耦；现有结构对逐信号有效性和控制域聚合状态表达不足 |
| Com / PduR / CanIf / CanSM / CanTp | 部分完成 | CAN 周期链路可用；CanTp 仅单帧；部分报文与矩阵不一致 |
| Dcm / Dem / NvM | 部分完成 | 教学链路可用；权限、字节序、去抖和规划一致性需修复 |
| Mcal CAN / I2C / SPI / Display / SDRAM / RTC | 已有实现 | 已有硬件调试记录；部分错误判定仍为近似或桩 |
| Mcal Mcu / Port / Dio / Pwm / Tim / Wdg | 桩或空壳 | 不应在能力清单中标为完整 MCAL |
| Os / EcuM | 原型可用 | FreeRTOS 任务和启动流程清晰；缺少产品级时间预算和任务监控闭环 |
| Config | 部分集中 | 已有 CAN/Com/Dem/Dcm/NvM 配置，但部分规则仍硬编码在 C 文件 |
| FatFs 日志 | 未完成 | `0x328` 当前仅提供可识别的桩状态 |
| 自动化测试 | 不完整 | 有人工测试文档和历史调试记录，缺少可重复的 CAN/UDS 回归脚本 |

## 4. 接口完整性

### 已具备

- GD32 CAN 收发主路径和过滤配置。
- 动力、车身、TPMS、配置等报文入口。
- 周期/事件发送框架。
- 物理/功能诊断 CAN ID 入口。
- 基础 DTC 查询、清除和持久化。

### 本次需闭环

- 接收逐信号有效性、报文超时、NM 在线和控制域健康必须分层表达。
- `0x325/0x326` 必须按矩阵重新编码。
- 增加 `0x329`，并在 UI 中可见控制域在线、健康、输入/电源模式和远端故障。
- DID、字节序和诊断权限以代码测试为准完成闭环。
- 所有“Supported”项必须能在源码中找到入口并在测试矩阵中找到验证用例。

## 5. 可靠性与安全性

| 项目 | 当前风险 | v1.0 对策 |
|---|---|---|
| CAN 无效值 | 可被换算为异常大物理量 | 先判断无效值，再换算；传播有效位 |
| 报文超时 | 多信号共用聚合有效位 | 按报文维护 freshness，并对关键报文维护逐信号有效性 |
| 控制域状态 | 只有 NM，无法解释降级原因 | 新增 0x329；NM 与健康状态分离 |
| 事件丢失 | 0x327 发送失败后事件已被消费 | 成功后清除，失败重试 |
| Dem 抖动 | 一次失败即确认 | 失败/通过阈值去抖 |
| NvM | 大块规划超过当前驱动能力 | 矩阵标注 Planned；保留现有块并制定迁移规则 |
| UDS 权限 | 功能寻址可执行状态改变 | 物理/功能权限白名单 |
| 软件声明 | 桩功能可能被误解为已完成 | UI、矩阵和报告明确 Stub/Planned |

## 6. P0 / P1 / P2 动作基线

为避免不同报告重复统计，本项目采用统一动作登记，共 **P0=13、P1=10、P2=6**。

### P0（本次接口定版必须关闭）

1. 0x321 无效值与 13-bit 车速处理。
2. 0x322 17 个车身信号完整解码。
3. 0x323 逐轮有效性和报警。
4. 0x325 按目标矩阵重构。
5. 0x326 按目标矩阵重构。
6. 0x441 NM 在线监督。
7. 0x329 控制域聚合状态与 E2E 校验。
8. DID 冲突和 UDS Big-Endian。
9. 物理/功能寻址权限隔离。
10. 核心单帧 UDS 服务一致性。
11. Dem 去抖和确认语义。
12. S32K144 按键引脚冲突冻结并回传。
13. Keil 构建及 CAN/UDS/回归测试证据。

### P1（本次关闭或明确受控降级）

1. 0x324 本机 NvM 与远端运行配置优先级。
2. 0x327 失败重试和去重语义。
3. 0x328 Stub 明示。
4. 0x440 NM 地址/状态修正。
5. 20 个 DTC 监控状态逐项标注。
6. 快照/扩展数据不支持状态明确。
7. NvM 实际映射、容量和迁移规则。
8. UI 显示控制域和完整车身/TPMS 状态。
9. PCAN/UDS 回归用例可重复执行。
10. 控制域离线时的本机降级策略。

### P2（后续产品化）

1. 完整 ISO-TP 多帧。
2. ECUReset/Security/WriteDID/IO/Routine/ControlDTCSetting。
3. 真实 FatFs 文件日志。
4. Dem 快照和扩展数据持久化。
5. DBC/ARXML 自动导出与双端一致性检查。
6. S32 控制域独立 UDS（建议 0x7E0/0x7E8）与联合诊断。

## 7. 完成判据

v1.0 完成必须同时满足：

- CAN 和诊断工作簿中无 DID/信号重复冲突，RevisionRecords 完整。
- 工作簿公式扫描无 `#REF!/#DIV/0!/#VALUE!/#NAME?/#N/A`。
- 代码能在当前 Keil 工程中完成全量构建。
- `0x321/0x322/0x323/0x329/0x441` 的正常、无效、超时场景有测试预期。
- `0x325/0x326/0x327/0x440` 的发送字节能逐字节核对。
- 物理/功能 UDS 权限和 DID BE 返回通过测试。
- P0 全部关闭；未关闭 P1/P2 在矩阵中标为 Stub 或 Planned。
