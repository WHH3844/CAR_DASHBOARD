# CAR_DASHBOARD UDS / Dem / NvM 诊断代码与矩阵差异报告

版本：v1.0  
日期：2026-07-29

## 1. 结论

当前诊断栈是可演示的单帧教学实现，不是完整 ISO-TP/UDS 产品栈。已实现的 UDS 核心服务具备清晰入口，但存在 DID 冲突、UDS 多字节返回采用 Little-Endian、功能寻址权限过大、Dem 一次失败即确认、NvM 规划与实际块结构不一致等问题。

本次 v1.0 完成：

- 唯一 DID 命名空间和代码对齐；
- UDS 多字节数据统一为 Big-Endian；
- 物理/功能寻址权限分离；
- `0x10/0x22/0x19/0x14/0x3E` 单帧路径定版；
- Dem 去抖和确认语义；
- 当前 NvM 实际占用、容量余量和后续迁移规则定版。

完整 ISO-TP 多帧、快照/扩展数据持久化、`0x11/0x27/0x2E/0x2F/0x31/0x85` 产品化支持列为后续版本。

## 2. UDS 服务 As-Built / Target

| SID | 服务 | As-Built | v1.0 权限与状态 |
|---|---|---|---|
| 0x10 | DiagnosticSessionControl | 支持默认/扩展会话，功能寻址也可切换 | 单帧支持；仅物理 `0x700` 可改变会话；功能寻址返回 NRC |
| 0x11 | ECUReset | 未支持 | 明确返回 ServiceNotSupported，列入后续 |
| 0x22 | ReadDataByIdentifier | 支持部分 DID，但 ID 冲突且多字节 LE | 物理和功能均可读；DID 唯一；多字节 BE |
| 0x19 | ReadDTCInformation | 支持 01/02，02 受单帧限制只返回首项 | 物理和功能只读允许；单帧响应明确截断规则，多帧列入后续 |
| 0x14 | ClearDiagnosticInformation | 支持 | 仅物理寻址允许；功能寻址禁止 |
| 0x27 | SecurityAccess | 未支持 | 未支持；所有需安全权限的写操作不可开放 |
| 0x2E | WriteDataByIdentifier | 未支持 | 未支持 |
| 0x2F | InputOutputControlByIdentifier | 未支持 | 未支持 |
| 0x31 | RoutineControl | 未支持 | 未支持 |
| 0x3E | TesterPresent | 支持 | 物理允许；功能允许无状态改变的 keep-alive 形式 |
| 0x85 | ControlDTCSetting | 未支持 | 未支持 |

## 3. DID 命名空间

| 范围 | 用途 |
|---|---|
| 0xF180..0xF19F | ECU 身份、硬件/软件和制造信息 |
| 0xF200..0xF21F | 运行时数据 |
| 0xF220..0xF23F | 配置数据 |
| 0xF240..0xF25F | 测试和调试结果 |

v1.0 代码支持的 DID：

| DID | 名称 | 数据 | 字节序 |
|---|---|---|---|
| 0xF191 | HardwareVersion | ASCII | N/A |
| 0xF193 | SoftwareVersion | ASCII | N/A |
| 0xF200 | BootCounter | uint32 | Big-Endian |
| 0xF201 | VehicleSpeed | uint16，0.1 km/h | Big-Endian |
| 0xF202 | EngineSpeed | uint16，rpm | Big-Endian |
| 0xF203 | BatteryVoltage | uint16，mV | Big-Endian |
| 0xF204 | RtcDate | 年、月、日（单帧） | 年份 uint16 为 Big-Endian；完整时间待 ISO-TP 多帧 |
| 0xF240 | SdramTestResult | uint8 | N/A |

原矩阵中 `03.SystemDID` 与 `04.ECU_DID` 复用了 `0xF180` 等 ID。v1.0 已将运行时 DID 迁移到 `0xF200` 范围；旧 ID 不保留隐式兼容，避免同一请求在不同版本中返回不同语义。

## 4. 字节序

- 标准 CAN 信号继续采用矩阵指定的 Intel/Little-Endian。
- UDS DID 数值、多字节长度、计数和时间中的 uint16/uint32 统一使用网络序/Big-Endian。
- ASCII 和独立字节数组不进行字节翻转。
- `LastFaultId` 等普通 CAN 接口字段不是 UDS 数据，仍按 CAN 矩阵的 Little-Endian。

## 5. 功能寻址权限

| 服务类别 | 0x700 物理寻址 | 0x7DF 功能寻址 |
|---|---|---|
| 读取 DID / DTC | 允许 | 允许 |
| TesterPresent | 允许 | 允许 |
| 会话切换 | 允许 | 禁止 |
| 清 DTC | 允许 | 禁止 |
| ECU Reset、写 DID、IO 控制、Routine、DTC 开关 | 实现且权限满足后才允许 | 禁止 |

功能寻址请求的响应策略沿用当前教学栈的“可返回 NRC”行为。未来与整车诊断网关联调时，可按项目规范切换为对部分功能请求静默，但权限边界不能放宽。

## 6. ISO-TP 多帧升级方案

当前 `CanTp` 只支持 Single Frame，单个 UDS 负载最多 7 字节。目标实现按以下顺序升级：

1. 增加 First Frame、Consecutive Frame、Flow Control 的收发状态机。
2. 校验 Sequence Number，支持 Block Size 和 STmin。
3. 增加 `N_Bs`、`N_Cr` 超时和错误恢复。
4. 将 Dcm 与固定 8 字节缓冲解耦，使用有界诊断缓冲区。
5. 为 `0x19 02` 多 DTC、长 ASCII DID 和快照数据增加多帧测试。

在多帧实现和回归通过前，矩阵中超过单帧能力的服务必须标为 Planned，禁止标为 Supported。

## 7. Dem 审计

当前定义 20 个事件。按“能否在当前代码/硬件中形成真实判定”分类如下，四类合计正好 20 项：

| 分类 | 数量 | 事件 | 审计结论 |
|---|---:|---|---|
| 真实检测逻辑 | 9 | CAN_BUS_OFF、CAN_RX_TIMEOUT、CAN_TRCV_ERROR、LCD_INIT_FAILED、SDRAM_INIT_FAILED、RTC_COMM_FAILED、RTC_TIME_INVALID、SHT30_COMM_FAILED、TF_CARD_MOUNT_FAILED | 源码存在 `Dem_ReportErrorStatus` 直接调用；仍需故障注入确认阈值和恢复 |
| 仅有事件定义 | 7 | SDRAM_RW_ERROR、FRAMEBUFFER_INVALID、EEPROM_COMM_ERROR、EEPROM_CRC_ERROR、KEY_STUCK、DISPLAY_TASK_OVERLOAD、WATCHDOG_RESET | 有事件 ID/配置，但没有完整周期监控入口 |
| 仅占位判据 | 3 | SUPPLY_VOLTAGE_LOW、SUPPLY_VOLTAGE_HIGH、POWER_HOLD_ERROR | 需求中有预期阈值或现象，当前缺少已确认的数据采集与判定闭环 |
| 当前硬件不可直接检测 | 1 | BUZZER_ERROR | 只有控制输出，没有蜂鸣器反馈/电流采样，不能把“发出控制命令”当作“蜂鸣器工作正常” |

源码中有直接监控调用的事件共 9 个：

- CAN_BUS_OFF
- CAN_RX_TIMEOUT
- CAN_TRCV_ERROR
- LCD_INIT_FAILED
- SDRAM_INIT_FAILED
- RTC_COMM_FAILED
- RTC_TIME_INVALID
- SHT30_COMM_FAILED
- TF_CARD_MOUNT_FAILED

其余 11 个事件只有配置定义、占位判据或缺少硬件反馈，尚无完整真实监控器：

- SUPPLY_VOLTAGE_LOW / HIGH
- SDRAM_RW_ERROR
- FRAMEBUFFER_INVALID
- EEPROM_COMM_ERROR / EEPROM_CRC_ERROR
- POWER_HOLD_ERROR
- KEY_STUCK
- BUZZER_ERROR
- DISPLAY_TASK_OVERLOAD
- WATCHDOG_RESET

v1.0 的 Dem 语义：

- 每个事件配置失败阈值和通过阈值。
- `PREFAILED`/失败样本达到阈值后才置 TestFailed 和 Confirmed。
- 连续通过样本达到恢复阈值后清 TestFailed；Confirmed 保留到 `0x14` 清除。
- 发生次数只在从非失败跃迁到已确认失败时递增，避免每个周期重复累计。
- DTC 数、LastFaultId 和 dirty 状态可供 `0x326` 和 UDS 查询。
- 快照和扩展数据在 v1.0 矩阵中标为 Planned，不伪装为已持久化。

## 8. NvM 审计与容量

FT24C16A 容量：2048 字节，地址 `0x000..0x7FF`。当前 NvM 每块头为 7 字节：Magic 2 + Version 1 + Length 2 + CRC16 2。

| 实际块 | 起始地址 | Payload | 含头占用 | 结束地址 |
|---|---:|---:|---:|---:|
| BootInfo | 0x700 | 8 | 15 | 0x70E |
| SystemConfig | 0x720 | 4 | 11 | 0x72A |
| DemStatus | 0x740 | 60 | 67 | 0x782 |

实际有效内容合计 93 字节；从首块起点到末块结束的地址跨度为 131 字节。末块之后到 EEPROM 末尾尚有 125 字节连续空间。整个 EEPROM 仍有较多低地址空间，但当前驱动的单块 payload 上限为 128 字节。

原诊断矩阵规划的 8 个 payload 合计 1248 字节，加 7 字节块头后为 1304 字节；若 DTC 状态块做一份冗余，约为 1567 字节，理论上小于 2048 字节。但当前实现不能直接承载 256/512 字节块，也没有完整的冗余切换、磨损均衡和原子提交机制，因此不能把“理论容量够”误写为“当前可实现”。

迁移要求：

1. 保留 `0x700/0x720/0x740` 三个已发布块地址和版本字段。
2. 新增大块前先升级 NvM 最大块长度及分段读写。
3. 双副本块必须包含 generation counter，并通过 CRC 和 generation 选新副本。
4. Dem 快照和扩展数据分块，不能一次写入 512 字节。
5. `NvMDirty` 仅表示存在待持久化数据，不表示写入成功。

## 9. 诊断测试重点

- 对每个支持 DID 校验 BE 字节序和无效输入行为。
- 分别从 `0x700` 和 `0x7DF` 请求 `0x10/0x14/0x22/0x19/0x3E`。
- 验证功能寻址不能改变会话、不能清 DTC。
- 失败样本未达到阈值时不得成为 Confirmed DTC。
- 达阈值后 `0x326` DTC count、UDS `0x19` 和 NvM dirty 必须一致。
- 重启后验证已保存 DTC 恢复，且块 CRC 错误时使用安全默认值并上报存储故障。
