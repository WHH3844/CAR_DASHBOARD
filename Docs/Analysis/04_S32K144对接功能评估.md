# S32K144 控制域对接功能评估

版本：v1.0  
日期：2026-07-29  
输入：`Docs/SCH_Schematic1_2026-07-26.pdf` 全部 9 页

## 1. 评估结论

S32K144 适合作为控制域 MCU，与 GD32 仪表域通过 CAN 交换 NM、健康、输入模式、电源模式和远端故障状态。现有 `0x441` 只能表达 NM 在线，信息量不足，因此 v1.0 新增 `0x329 CDM_Status_500ms`。

原理图中的五个按键均为 **10 kΩ 上拉到 VCC_MCU、100 nF 对地滤波、按下接地、低电平有效**。但需求给出的引脚表与原理图实际网名不一致，且 `PTC12` 已用于 `CAN2_ERRN`，属于 P0 接口冲突。本轮只审计并冻结接口，不修改任何 S32K144 工程。

## 2. 原理图关键接口

### CAN

| 接口 | MCU 管脚/控制 | 说明 |
|---|---|---|
| CAN1 | PTA12/PTA13，控制 PTA14/PTA15/PTA16 | 控制域主 CAN，可用于与 GD32 仪表域通信 |
| CAN2 | PTC16/PTC17，控制 PTC10/PTC11/PTC12 | 第二路 CAN；PTC12 为 CAN2_ERRN |

### 按键实际连接

| 按键 | 原理图实际 MCU 引脚 | 电气 | 与需求期望比较 |
|---|---|---|---|
| KEY1 | PTC13 | 上拉、RC、按下为低 | 需求写 PTC12；不一致 |
| KEY2 | PTB2 | 上拉、RC、按下为低 | 需求写 PTC13；不一致 |
| KEY3 | PTB3 | 上拉、RC、按下为低 | 需求写 PTB2；不一致 |
| KEY4 | PTC14 | 上拉、RC、按下为低 | 需求写 PTB3；不一致 |
| KEY5 | PTC15 | 上拉、RC、按下为低 | 需求写 PTC14；不一致 |
| CAN2_ERRN | PTC12 | CAN2 收发器错误输入 | 与需求 KEY1=PCT12 冲突 |

联合调试前，S32 固件负责人必须以原理图网名表为准确认 pin mux，并回签：

```text
KEY1=PTC13, KEY2=PTB2, KEY3=PTB3, KEY4=PTC14, KEY5=PTC15
```

不得把 PTC12 配置为按键 GPIO，否则会破坏 CAN2 错误状态输入。

## 3. 跨域报文职责

| ID | 方向 | 职责 |
|---|---|---|
| 0x441 | S32K144 -> GD32 | NM 心跳、节点在线和基本 NM 状态 |
| 0x329 | S32K144 -> GD32 | 控制域聚合状态：接口版本、输入/电源/健康模式、远端 DTC 摘要、总线状态、AliveCounter、CRC8 |
| 0x440 | GD32 -> S32K144 | 仪表域 NM 心跳 |
| 0x325/0x326 | GD32 -> S32K144 | 仪表运行状态和诊断摘要 |
| 0x327 | GD32 -> S32K144 | 按键事件 |

`0x441` 不扩展成 8 字节健康报文的原因：

1. NM 与应用健康的生命周期和超时不同。
2. NM 报文应保持简单和稳定，避免应用字段变化影响在线判定。
3. `0x329` 可独立版本化并提供 AliveCounter + CRC。

## 4. 输入模式

控制域支持以下输入模式编码：

| 值 | 模式 | GD32 行为 |
|---:|---|---|
| 0 | SIM | 显示控制域为仿真输入，不把变化解释为真实 ADC |
| 1 | ADC | 接受 ADC 相关有效标志 |
| 2 | FIX | 显示固定/标定值模式 |
| 3 | Invalid | 将控制域输入状态标无效并降级 |

按键去抖应在 S32 源端完成，GD32 只接收已经确认的状态或事件，不重复进行会改变语义的长按判断。

## 5. 控制域健康与故障

`0x329` 同时满足：

- 快速判断控制域是 OK、DEGRADED 还是 FAULT。
- 显示远端活动故障数量和 LastRemoteFaultId。
- 区分 CAN1/CAN2/LIN1/LIN2/ADC 是否有效。
- 通过 `InterfaceVersion=0x10` 检测矩阵版本。
- 通过 AliveCounter 检测发送任务冻结。
- 通过 CRC8/J1850 检测应用层字段、ID 和版本的一致性。

GD32 不能把远端 LastFaultId 写入本地 Dem 作为相同 DTC。应分别显示“本地 DTC”和“控制域故障”，避免清本地 DTC 时误认为已经清除 S32 故障。

## 6. 诊断地址规划

当前 GD32 物理 UDS：请求 `0x700`，响应 `0x708`；功能请求 `0x7DF`。

若 S32 后续提供独立 UDS，建议使用：

- S32 请求 `0x7E0`
- S32 响应 `0x7E8`

最终地址需经整车网络架构确认。未确认前，S32 只通过 `0x329` 提供诊断摘要，不代理清故障和写配置。

## 7. 离线与降级

| 条件 | 判定 | ICM 行为 |
|---|---|---|
| 0x441 超过 3000 ms | NM 离线 | 显示 CDM Offline；保持本机功能 |
| 0x329 超过 1500 ms | 应用状态 stale | 清远端状态有效位；保留最后 ID 并标 stale |
| CRC 错误 | 当前帧无效 | 丢弃当前状态，记录统计 |
| AliveCounter 连续不变 | 发送任务疑似冻结 | Health 降级 |
| InterfaceVersion 非 0x10 | 接口版本不兼容 | 不解析其余字段，显示版本错误 |

## 8. S32 侧交付清单

1. 按原理图实际网名确认五个按键 pin mux 和低有效逻辑。
2. 确认 CAN1/CAN2 中哪一路承载与 GD32 的接口。
3. 按 `0x329` 定版布局发送，CRC 覆盖 ID + B0..B6。
4. AliveCounter 每个成功发布周期递增，不能只在值变化时递增。
5. `LastRemoteFaultId` 使用接口 ID 表，不直接复用本地数组下标。
6. 提供 0x329 正常、CRC 错误、计数器冻结和超时测试帧。
