# CAR_DASHBOARD CAN 代码与矩阵差异报告

版本：v1.0  
日期：2026-07-29  
审计范围：`App/`、`Rte/`、`Bsw/`、`Mcal/`、`Os/`、`Config/`、Keil 工程、原始 CAN 矩阵和 S32K144 原理图。

## 1. 审计结论

原始 CAN 矩阵与当前 GD32 实现之间共有 **60 项信号级差异**，另有 3 项跨报文行为差异：

1. `0x327` 事件在发送失败时会丢失，缺少“成功发送后清除”的重试语义。
2. `0x328` 是教学桩实现，没有真实 FatFs 文件序号和错误状态。
3. CAN 接收有效性被聚合成少量布尔量，不能区分单信号无效、报文超时和控制域离线。

本次定版保留标准 CAN 报文内的 Intel/Little-Endian 约定，并新增 `0x329 CDM_Status_500ms`。`0x441` 继续仅承担 NM/在线监督，不能替代控制域健康、输入模式、电源模式和远端故障状态。

## 2. 报文审计矩阵

| ID | 方向（相对 ICM） | As-Built | Target v1.0 | 级别 |
|---|---|---|---|---|
| 0x321 | Rx | 6 个动力信号均解码，但车速未屏蔽 13 bit，无效值仍参与物理量换算，仅有整帧有效标志 | 逐信号判断无效值，车速使用 `raw & 0x1FFF`，任一无效值不得生成异常大物理量；100 ms 超时 | P0 |
| 0x322 | Rx | 只实现点火、挡位和 Byte3 四个故障灯 | 完整实现车门、驾驶员安全带、远近光、转向/双闪、驻车、洗涤液和环境光；500 ms 超时 | P0 |
| 0x323 | Rx | 8 个字节均解码，但无 `0xFF` 判断、无轮位独立有效性/报警 | 压力/温度逐轮有效，`0xFF` 无效，提供 4 轮报警位；3000 ms 超时 | P0 |
| 0x324 | Rx | 字段基本解码，缺少无效值规则；外部值直接覆盖运行配置 | 增加范围和无效值校验；本机 NvM 是上电基线，合法远端配置只作本次运行期覆盖，重启后仍以 NvM 为准；3000 ms 超时 | P1 |
| 0x325 | Tx | 发送车速、转速、状态位和计数器，与原矩阵完全不符 | 按定版发送 ICM 模式、页面、蜂鸣器、实际背光、里程、驾驶时间、关机请求和故障灯请求 | P0 |
| 0x326 | Tx | 仅 DTC 数、会话、动力报文有效和计数器 | 发送 DTC 数、LastFaultId、上电次数、自检状态、CAN 状态、Bus-Off 次数、复位原因、诊断会话、NvM dirty 和 SelfTestPassed | P0 |
| 0x327 | Tx | 字段布局匹配；先清事件再调用发送 | 保持布局，计数器自然回卷；仅在成功交付 CanIf 后清事件，失败保留并重试 | P1 |
| 0x328 | Tx | 发送桩状态、固定文件号和运行秒数 | 明确标注 Stub：未挂载、串口日志启用、文件号为 0；真实 FatFs 日志列入后续版本 | P1 |
| 0x329 | Rx | 不存在 | 新增控制域聚合状态，含接口版本、输入/电源/健康模式、远端故障、总线状态、AliveCounter 和 CRC8/J1850；1500 ms 超时 | P0 |
| 0x440 | Tx | 节点地址为 `0x28`，状态位不符合矩阵语义 | 节点地址改为 `0x40`；正常运行时 `NMState=NormalOperation`，重复请求/激活位按状态发送 | P1 |
| 0x441 | Rx | 未处理 | 解析控制域 NM，维护独立在线状态和 3000 ms 超时；不承担健康和故障聚合 | P0 |
| 0x700/0x708 | Rx/Tx | 单帧 UDS 可工作 | 保持物理寻址；功能寻址与物理寻址权限分离 | P0 |
| 0x7DF | Rx | 与物理寻址权限相同 | 仅允许只读类服务，禁止会话切换、清 DTC 和任何状态改变操作 | P0 |

## 3. 0x329 新增报文定义

报文名：`CDM_Status_500ms`  
发送节点：S32K144/CDM  
接收节点：GD32/ICM  
DLC：8  
周期：500 ms  
接收超时：1500 ms

| Byte/Bit | 信号 | 编码 |
|---|---|---|
| B0 | InterfaceVersion | `0x10` 表示 v1.0 |
| B1.0..1 | InputMode | 0=SIM，1=ADC，2=FIX，3=Invalid |
| B1.2..4 | PowerMode | 0=OFF，1=ACC，2=RUN，3=START，7=Invalid |
| B1.5..6 | HealthState | 0=OK，1=DEGRADED，2=FAULT，3=Invalid |
| B1.7 | RemoteFaultPresent | 1=控制域存在活动故障 |
| B2 | RemoteDtcCount | 0..254，`0xFF` 无效 |
| B3.0..6 | 状态位 | CAN1/CAN2/LIN1/LIN2/ADC 有效、KeyOverride、SelfTestPassed |
| B4..5 | LastRemoteFaultId | Intel/LE，`0xFFFF` 无效；不是 UDS 24-bit DTC |
| B6 | AliveCounter | uint8，0xFF 后回卷到 0 |
| B7 | CRC8 | SAE J1850：poly=0x1D，init=0xFF，xorout=0xFF；覆盖 CAN ID 低字节、高字节及 B0..B6 |

应用层 CRC 的取舍：CAN 控制器本身已有帧 CRC，但无法覆盖“报文 ID、计数器与应用语义是否来自同一接口版本”的端到端一致性。`0x329` 是跨控制器聚合状态，因此 v1.0 保留 AliveCounter + CRC8；普通状态报文不追加应用 CRC。

## 4. 接收有效性与降级规则

1. “收到 CAN 帧”不等于“全部信号有效”。`0x321` 和 `0x323` 必须维护逐信号有效位。
2. 首帧到达前、超时后或无效值出现时，UI 显示占位符或保持安全默认值，不显示由无效 raw 换算出的超大数字。
3. `0x329` CRC 错误或 AliveCounter 连续不变化时，控制域状态降级；`0x441` 超时只判定 NM 离线。
4. `0x329` 和 `0x441` 任一超时不得影响本机 LCD、按键、RTC、SHT30 和本机诊断的可用性。
5. 控制域离线时清除远端瞬时状态的有效位，但保留最后故障 ID 供维护界面显示，并明确标记为 stale。

## 5. 发送行为

- 周期发送：`0x325` 100 ms、`0x326` 1000 ms、`0x328` 1000 ms、`0x440` 1000 ms。
- 事件发送：`0x327` 的事件计数器按每个被接受的事件递增，发送失败不丢事件。
- `TripDistance` 在尚无可靠里程源时发送 `0xFFFF`，禁止以运行时间或车速临时伪造。
- `LastFaultId` 是本地 Dem 事件号的接口 ID，不与 UDS DTC 24-bit 编码混用。
- `0x328` 在 FatFs 尚未接入时必须发送明确的“未挂载/桩”状态。

## 6. 风险与动作

| 编号 | 风险 | 处理 |
|---|---|---|
| CAN-P0-01 | 无效车速/转速进入 UI 或诊断 | 本次修复 |
| CAN-P0-02 | 车身状态只实现 6/17 个信号 | 本次补齐 |
| CAN-P0-03 | TPMS 无轮位有效性 | 本次补齐 |
| CAN-P0-04 | 0x325/0x326 与矩阵不一致 | 本次重构 |
| CAN-P0-05 | 0x441 无在线监督 | 本次补齐 |
| CAN-P0-06 | 控制域聚合状态缺失 | 本次新增 0x329 |
| CAN-P1-01 | 0x327 发送失败丢事件 | 本次修复 |
| CAN-P1-02 | 0x328 被误认为真实文件日志 | 文档和状态显式标注，真实 FatFs 后续实现 |
