# 架构落地调试记录

## 2026-06-03 目标

PCB 板级测试已经完成，本次目标是把 `12_dashboard_demo` 的硬件联调能力迁移到正式 Mini AUTOSAR-like 架构中，让工程从测试闭环进入可继续扩展的主线工程。

## 已确认的硬件基线

- 电源自锁：`KEY_POWER=PC13`，`PWR_HOLD=PE3`，软开关流程已在前期测试中反复验证。
- SDRAM：W9825G6KH-6I，EXMC 参数保持与可显示的 `RGB_800x480_DEMO` 一致。
- LCD：800x480 RGB565，TLI 参数为 `HSYNC=10/HBP=150/HFP=15/VSYNC=10/VBP=140/VFP=40`，DE 低有效。
- CAN：CAN1，PB13/PB12，SIT1043QT，500K，标准帧收发已通过 PCAN-View。
- I2C0：PB6/PB7，扫描到 SHT30 `0x44`、FT24C16A `0x50~0x57`、DS3231 `0x68`。
- EEPROM：FT24C16A `0x0100` 测试写读通过。
- RTC：DS3231 时间读写和 CR1220 后备供电通过。
- SHT30：温湿度读取和 CRC 校验通过。
- TF 卡：SDIO 只读阶段通过，0 号扇区 `55 AA` 签名正常。
- 按键/蜂鸣器：KEY1/KEY2/KEY3 和 PF9 蜂鸣器驱动通过。

## 本次代码落地步骤

1. 增加 `Std_Types.h`，统一 `Std_ReturnType/E_OK/E_NOT_OK`。
2. 补齐配置文件：`Can_Cfg.h`、`Com_Cfg.h`、`Dcm_Cfg.h`、`Dem_Cfg.h`、`NvM_Cfg.h`、`Rte_Cfg.h`、`App_Cfg.h`。
3. 实现 `LogM` 和 `Crc`，为后续日志、NvM CRC 打基础。
4. 实现 `CanTrcv/CanIf/CanSM/PduR/CanTp/Com`：
   - `CanIf` 调用已验证的 `Can1_Init500K/Can1_Read/Can1_SendStd`。
   - `PduR` 按 ID 把诊断帧送 `CanTp/Dcm`，把业务帧送 `Com`。
   - `Com` 解析 `0x321/0x322/0x324`，并发送 `0x325/0x326/0x440`。
5. 实现 `NvM`：
   - EEPROM 块格式为 magic/version/length/crc/payload。
   - 保存启动次数、系统配置、DTC 状态。
6. 实现 `Dem`：
   - 管理 20 个 DTC。
   - 支持 failed/passed、confirmed、warning indicator、occurrence counter。
   - 支持按 status mask 查询和清全部故障。
7. 实现 `Dcm`：
   - 支持 `0x10/0x22/0x19/0x14/0x3E`。
   - 当前只做单帧 ISO-TP，兼容手工裸 UDS 请求。
8. 实现 `RTE`：
   - 统一保存车速、转速、电压、RTC、温湿度、按键、报警等信号。
   - APP 不再直接解析 CAN，也不直接读取底层驱动。
9. 实现 `SdramMgr/SdramIf/LcdIf/BacklightIf`：
   - SDRAM 和 LCD 仍复用前期已验证参数。
   - 显示层提供局部刷新，避免整屏频繁擦写造成 SDRAM/TLI 争用。
10. 实现 `App_Key/App_Dashboard/App_Display/App_Sensor/App_Power`。
11. 实现 `EcuM/Os`：
   - `main.c` 改为只调用 `EcuM_Init()` 和 `EcuM_MainLoop()`。
   - 当前仍为裸机 super loop，不引入 FreeRTOS。

## 板上验证建议

1. 先不接 CAN，只上电看串口和 LCD：
   - 串口应看到 EcuM 进入 RUN。
   - LCD 应显示 Dashboard 主界面。
   - 未收到 `0x321` 时显示 `CAN LOST`。
2. 按 KEY1：
   - 进入模拟模式，LCD 显示 `SIM MODE`。
   - 速度/转速应周期变化。
3. 用 PCAN 周期发送 `0x321`：
   - KEY1 关闭模拟模式。
   - LCD 应显示 `CAN OK`。
   - 速度、转速按报文变化。
4. 诊断测试：
   - 请求 ID `0x700`，响应 ID `0x708`。
   - 先测 `0x10/0x3E/0x22`，再测 `0x19/0x14`。
5. 掉电重启：
   - 读 DID `0xF180`，启动次数应增加。
   - DTC 状态应能通过 EEPROM 保持。

## 风险和后续 TODO

- 当前 `CanTp` 只支持单帧，长 DID、完整 DTC 列表、快照和扩展数据还不能完整返回。
- 当前背光接口只有开关，硬件 PWM 亮度控制后续再接。
- 当前 LCD 文本绘制是轻量自绘，不是 LVGL。
- 当前 NvM 是同步 byte write，适合学习验证，后续应改成延迟写和写队列，减少 EEPROM 写入阻塞。
- 当前 CAN Bus-Off 只用错误计数近似判断，后续应读取更准确的控制器状态位。
