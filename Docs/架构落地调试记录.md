# CAR_DASHBOARD 架构落地调试记录

## 2026-06-03：从板级测试工程切到正式架构工程

### 背景

PCB 第一轮硬件 bring-up 已完成，`12_dashboard_demo` 已验证：

- 电源自锁、长按关机、UART 下载调试正常
- SDRAM 初始化参数可稳定支撑 LCD framebuffer
- 800x480 RGB LCD 使用 TLI + SDRAM framebuffer 显示正常
- CAN1 500K 与 PCAN-View 收发正常
- I2C0 上 EEPROM、RTC、SHT30 地址和功能正常
- TF 卡 SDIO 只读识别正常
- KEY1/KEY2/KEY3 和蜂鸣器正常

因此本轮目标不再是继续写单独测试程序，而是把已验证的外设能力沉淀到 Mini AUTOSAR-like 分层架构。

### 本轮完成内容

1. 公共配置和基础类型：新增 `Std_Types.h`，补齐 CAN、Com、Dcm、Dem、NvM、RTE、APP 配置。
2. BSW 通信链路：实现 `CanIf`、`CanTrcv`、`PduR`、`CanTp`、`Com`。
3. RTE 信号层：建立车速、转速、电压、RTC、SHT30、按键、蜂鸣器和 CAN 有效性信号。
4. 诊断和故障管理：`Dcm` 支持 `0x10/0x22/0x19/0x14/0x3E`，`Dem` 支持 20 个 DTC 的最小状态管理。
5. NvM：使用 FT24C16A 保存启动次数、系统配置和 Dem 状态，增加 CRC16。
6. APP：实现按键、传感器、仪表业务、LCD 局部刷新、软关机前保存 NvM。
7. EcuM / Os：`main.c` 改为干净入口，`Os` 已接入 FreeRTOS，并保留裸机 super loop 回退模式。

### 关键调试经验

- LCD 花屏根因不是引脚，而是 SDRAM 参数不适合 TLI 连续读取；正式架构保留已验证的 EXMC 参数。
- 显示层只做局部刷新，避免 500ms 内频繁整屏清 framebuffer。
- CAN 诊断目前只做单帧，长 DID、DTC 快照、多帧刷写留给 CanTp 第二阶段。
- EEPROM 写入通过 NvM 延迟写，避免业务逻辑直接高频写 FT24C16A。
- FreeRTOS 先放在 Os 层，当前只创建一个 `EcuM` 主任务承载原 10ms 调度，避免第一版就引入多任务共享资源竞争。

### 当前验证风险

- FreeRTOS 已加入 Keil 工程并完成命令行构建，日志显示 `0 Error(s), 0 Warning(s)`。
- `APP_CFG_USE_FREERTOS` 默认是 `1u`；若板上排查 RTOS tick、任务栈或中断优先级问题，可临时改为 `0u` 回退裸机。
- 下一步风险从“能否编过”变为“板上能否稳定运行 2 小时以上”，重点观察 LCD 花屏、CAN 丢帧、I2C 超时和 NvM 写入节奏。

## 2026-06-03：FreeRTOS 移植记录

### 为什么现在加入 FreeRTOS

前面 12 个板级测试和 `12_dashboard_demo` 已经证明主要硬件通路能跑通，因此可以把 RTOS 加进正式工程。这样项目完整度更高，也能在面试时说明自己知道裸机调度和 RTOS 调度的差异。

### 本次移植选择

- FreeRTOS 来源：`D:\MCU\FreeRTOSv202212.01\FreeRTOS\Source`
- MCU 内核：GD32F470 Cortex-M4F
- 端口目录：`portable/RVDS/ARM_CM4F`
- 堆管理：`portable/MemMang/heap_4.c`
- 工程内路径：`Os/FreeRTOS/Source`
- 配置文件：`Config/FreeRTOSConfig.h`

### 关键处理

1. 向 Keil 工程加入 `tasks.c`、`queue.c`、`list.c`、`timers.c`、`event_groups.c`、`stream_buffer.c`、`heap_4.c`、`port.c`。
2. 增加 FreeRTOS include 路径：`Source/include`、`portable/RVDS/ARM_CM4F`、`portable/MemMang`。
3. 在 `FreeRTOSConfig.h` 中把 `vPortSVCHandler`、`xPortPendSVHandler`、`xPortSysTickHandler` 映射到启动文件使用的 `SVC_Handler`、`PendSV_Handler`、`SysTick_Handler`。
4. `Os_Start()` 创建一个 `EcuM` 主任务，任务里使用 `vTaskDelayUntil()` 保持 10ms 周期。
5. `Os_DelayMs()` 在调度器启动前使用忙等，在调度器启动后自动切换为 `vTaskDelay()`。
6. 增加 `vApplicationMallocFailedHook()` 和 `vApplicationStackOverflowHook()`，出现堆不足或任务栈溢出时停机，便于调试定位。
